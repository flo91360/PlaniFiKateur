Connecter votre agent

La description de la carte constitue la demande transmise à l’agent. Celui-ci en déduit le résultat attendu et les vérifications utiles. Le parcours dans le site est prêt. Pour qu’une carte soit réellement traitée, lancez le worker Codex dans un service séparé.

  1. Dans « Paramètres du projet », un administrateur renseigne le dépôt GitHub et crée la clé dans « Connexion de l’agent ». Ces réglages s’appliquent à toutes les cartes du projet.
  2. Placez la clé dans les secrets du service agent. Utilisez HTTPS et l’en-tête Authorization: Bearer <clé-agent>.
  3. L’agent consulte GET /api/v1/projects/{projet}/work et réserve une exécution avec POST /api/v1/projects/{projet}/cards/{carte}/work/{execution}/claim et sa version.
  4. Il confirme sa présence toutes les 60 secondes avec heartbeat, puis utilise question, progress ou submit. La réservation expire après cinq minutes sans réponse.
  5. Passez la carte au statut « Prête à démarrer » : le worker la détecte automatiquement. Dans « Tâches du projet », sélectionnez-la pour répondre aux questions et suivre le résultat. Toutes les nouvelles tâches sont terminées après tests et fusion automatiques de leur PR GitHub. L’agent reprend une tâche corrigée en la réservant à nouveau.

Le client de référence scripts/agent-client.mjs dans le dépôt facilite les appels. Le site ne lance pas directement de modèle. Le worker Codex du dépôt utilise le SDK pour modifier le code, lancer les tests et ouvrir une PR.
